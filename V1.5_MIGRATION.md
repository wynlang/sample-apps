# Wyn v1.5.0 Migration Guide for Sample Apps

This guide shows how to upgrade existing Wyn applications to use v1.5.0's modern type system features.

## ⚠️ Syntax Limitations in v1.5.0

v1.5.0 has some verbose syntax that will be improved in v1.6.0:

- Enum constructors use underscores: `Result_Ok(42)` instead of `Ok(42)`
- HashMap needs type annotations: `var map: HashMap<K,V> = {}` instead of `var map = HashMap<K,V>{}`
- Pattern matching uses full names: `Result_Ok(x)` instead of `Ok(x)`

**The type system works correctly** - these are just syntax limitations being addressed in the next release.

## New Features Available

### 1. Enums with Associated Data
Replace error codes with type-safe enums:

**Before (v1.4):**
```wyn
fn process_data(input: string) -> int {
    if input.len() == 0 {
        return -1  // Error code
    }
    return 0  // Success
}
```

**After (v1.5):**
```wyn
enum Result {
    Success(int),
    Error(string)
}

fn process_data(input: string) -> Result {
    if input.len() == 0 {
        return Result_Error("Empty input")
    }
    return Result_Success(0)
}
```

### 2. Pattern Matching
Replace if-else chains with elegant pattern matching:

**Before (v1.4):**
```wyn
fn handle_result(code: int) -> int {
    if code == 0 {
        print("Success")
        return 1
    } else {
        print("Error")
        return 0
    }
}
```

**After (v1.5):**
```wyn
fn handle_result(result: Result) -> int {
    var value = match result {
        Result_Success(n) => n,
        Result_Error(msg) => 0
    }
    return value
}
```

### 3. Generic HashMap
Replace arrays with type-safe HashMaps:

**Before (v1.4):**
```wyn
// Limited to arrays
var scores = [95, 87, 92]
```

**After (v1.5):**
```wyn
var scores: HashMap<string, int> = {}
scores.insert("alice", 95)
scores.insert("bob", 87)
scores["charlie"] = 92  // Variable keys work!
```

### 4. Option Type
Replace null checks with Option:

**Before (v1.4):**
```wyn
fn find_user(name: string) -> int {
    // Return -1 for not found
    return -1
}
```

**After (v1.5):**
```wyn
enum Option {
    Some(int),
    None
}

fn find_user(name: string) -> Option {

        return Option_Some(score)
    }
    return Option_None()

// Use with methods
var result = find_user("alice")
if result.is_some() {
    print(result.unwrap().to_string())
}
```

### 5. String Indexing
Access characters directly:

**Before (v1.4):**
```wyn
// No direct character access
```

**After (v1.5):**
```wyn
var text = "Hello"
var first = text[0]  // "H"
var last = text[4]   // "o"
```

### 6. Type Inference
Let the compiler infer types:

**Before (v1.4):**
```wyn
// Manual type annotations everywhere
```

**After (v1.5):**
```wyn
fn create_map() -> HashMap<string, int> {
    var map: HashMap<string, int> = {}
    return map
}

var my_map = create_map()  // Type inferred!
my_map.insert("key", 100)  // Methods work!
```

## Application-Specific Upgrades

### Data Processing Apps

**Log Analyzer** - Add error handling with Result:
- Replace error codes with `Result<T, E>`
- Use pattern matching for log level classification
- HashMap for log statistics

**CSV Processor** - Add validation with enums:
- `ValidationResult` enum for row validation
- Pattern matching for field processing
- HashMap for column mapping

**Text Processor** - Add Option for lookups:
- Option type for word lookups
- HashMap for word frequency
- String indexing for character analysis

### Networking Apps

**HTTP Client** - Add response handling:
- `HttpResult` enum for responses
- Pattern matching for status codes
- HashMap for headers

### Web Apps

**Web Server** - Add request routing:
- `Route` enum for endpoints
- Pattern matching for request handling
- HashMap for route mapping

### Utilities

**File Finder** - Add search results:
- `SearchResult` enum
- Option for file lookups
- HashMap for file metadata

**Process Monitor** - Add process states:
- `ProcessState` enum
- Pattern matching for state transitions
- HashMap for process info

## Migration Checklist

For each app:

- [ ] Replace error codes with Result enums
- [ ] Add pattern matching for control flow
- [ ] Use HashMap for key-value data
- [ ] Add Option for nullable values
- [ ] Use string indexing where appropriate
- [ ] Leverage type inference
- [ ] Add enum methods (unwrap, is_some, etc.)
- [ ] Update tests to use new features

## Benefits

1. **Type Safety** - Compiler catches more errors
2. **Readability** - Intent is clearer
3. **Maintainability** - Less boilerplate
4. **Ergonomics** - Better APIs
5. **Performance** - Zero-cost abstractions

## v1.6.0 Syntax Improvements

The following syntax improvements are planned:

**Enum constructors:**
```wyn
// v1.5.0 (current)
var result = Result_Ok(42)

// v1.6.0 (planned)
var result = Ok(42)  // or Result::Ok(42)
```

**HashMap initialization:**
```wyn
// v1.5.0 (current)
var map: HashMap<string, int> = {}

// v1.6.0 (planned)
var map = HashMap<string, int>{}
```

**Pattern matching:**
```wyn
// v1.5.0 (current)
match result {
    Result_Ok(x) => x,
    Result_Err(e) => 0
}

// v1.6.0 (planned)
match result {
    Ok(x) => x,
    Err(e) => 0
}
```

These improvements will make the syntax as clean as the type system is powerful.
